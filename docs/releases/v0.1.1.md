# Akamata v0.1.1

Akamata v0.1.1 fixes reentrancy in the Cloudflare Workers WebAssembly bridge.

Highlights:

- The complete WASM HTTP ABI transaction is serialized per isolate, including
  request allocation, JSPI-suspended `handle_fetch`, response pointer/length
  reads, response copying, and buffer deallocation.
- HTTP, realtime service-entrypoint calls, and Queue deliveries share the same
  serialization boundary, protecting the allocator and bridge registries.
- Concurrent first-request WASM initialization is coalesced.
- Invalid WASM response status lines now produce a diagnostic `502` instead of
  throwing from the Workers `Response` constructor.
- A 256-request concurrent regression test verifies response and allocator
  isolation while dispatches suspend asynchronously.

The Akamata CLI reports version 0.1.1, and newly generated projects pin their
framework dependency to the immutable v0.1.0 release archive.

For the detailed change list, see [CHANGELOG.md](../../CHANGELOG.md).
