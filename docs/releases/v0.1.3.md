# Akamata v0.1.3

Akamata v0.1.3 makes existing applications safer to synchronize and adds a
focused set of reusable application building blocks.

Highlights:

- Capability-aware `akamata sync` preserves D1, R2, Queue, and Realtime glue
  instead of replacing a project with the minimum Worker template.
- `am.model.Query`, arbitrary DTO `fetchAll`, partial updates, shared row
  mapping, and batch `preload.belongsTo` cover common data access while raw SQL
  remains available for joins and complex predicates.
- `validatedJson`, portable crypto, session identity/revoke helpers,
  Origin/Fetch-Metadata/session-bound CSRF, standard error mapping, typed
  config, idempotency, storage factory, and typed management commands reduce
  repeated application plumbing.
- Testing helpers now include cookie jars, auth/CSRF requests, multipart
  bodies, response assertions, in-memory SQLite integration, and capability
  sync regressions.
- D1 transactions continue to fail closed; the new guidance recommends
  single statements, constraints/triggers, batches, and idempotent workflows
  without transaction emulation.

Existing public APIs remain compatible. The new APIs are additive.

Recommended upgrade:

```bash
akamata update --to=v0.1.3 --sync --dry-run
akamata update --to=v0.1.3 --sync
git diff
```
