# Akamata v0.2 Design — Complete Transparency + Feature Enhancements + Turso

> Historical planning document. Statements about missing or planned features describe the pre-v0.2 state and are not current support information. Use the documentation home and current source for supported behavior.

Designing the next milestone based on the 3 requirements of todo_2.md.

## 1. Review of current situation (Audit summary)

### 1.1 Cloudflare / VPS Transparency

| Layer | Transparency | Current status |
|---|---|---|
| Handler API (`am.Context`) | ★★★★★ | Completely identical |
| App Builder (`am.App`) | ★★★★★ | Completely the same |
| HTTP client | ★★★★★ | API same (implementation is divergent) |
| Env vars | ★★★★★ | API same |
| **DB initialization** | ★★★☆☆ | **Need to select `openSqlite`/`openD1` in comptime** |
| FCM push | ★★★☆☆ | Not implemented on Workers side |
| MQTT | ★☆☆☆☆ | Native only, UnsupportedOnTarget for Workers |
| WebSocket upgrade | ★★☆☆☆ | Workers side DO via is undeveloped, handler branch |
| File I/O | ★☆☆☆☆ | Workers is volatile, no abstraction |
| `serve()` opts | ★☆☆☆☆ | Workers ignore `opts` |

**Overall**: ``**Handler body is transparent, initialization (`main`/`worker.zig`) and external I/O system require environmental awareness**'' is the reality.

### 1.2 Feature gap (Hono/Express/FastAPI ratio)

★★★★★ Critical:
- **multipart/form-data** (file upload) — todo_2.md explicit request
- form-urlencoded body
- Cookie reading and writing
-Session middleware

★★★★ High:
- `req.ip` / `X-Forwarded-For`
- OAuth2 Authorization Code Client
- Rate limit middleware
- Room/topic broadcast (WS pub/sub)

★★★ Medium:
-Streaming response/SSE
- ETag / If-None-Match (304)
- Structured JSON log + `request_id` automatic assignment
- OpenAPI schema automatic generation
- typed config loader

### 1.3 Turso/libsql

- Recommended: Method of hitting **Hrana v3 HTTP** via `am.http_client` (Completely common to Workers/native)
- D1's 2-pass coroutine problem does not occur (Hrana is completed with 1 req=1 res)
- Reuse the existing `am.db.Db` vtable as is, and maintain Stmt compatibility
- Embedded replicas are supported with a separate flag in P3 (requires libsql-c Rust toolchain)

| | Contents |

## 3. API Sketch

### 3.1 Unified DB Factory

```zig
// 1 行で書ける、両環境で動く
var db = try am.db.open(gpa, "file:./chat.db");
// or
var db = try am.db.open(gpa, "libsql://my-app-org.turso.io?token=" ++ secret);

// Handler はそのまま
fn createRoom(c: *am.Context(App)) !void {
    var stmt = try c.state().db.prepare("INSERT INTO rooms(name) VALUES(?)");
    defer stmt.deinit();
    try stmt.bindAll(.{"general"});
    _ = try stmt.step();
}
```

URL schema interpretation:
- `file:path` → SQLite (native)
- `libsql://host?token=…` → Turso Hrana HTTP (native + Workers)
- `https://host` is also treated as libsql (Turso accepts both)
- `d1://binding` → D1 (Workers, legacy)

If you pass `file:` in Workers, it becomes `@compileError("file: requires native backend")` at compile time or `error.BackendMismatch` at runtime.

### 3.2 File upload

```zig
const Upload = struct {
    name: []const u8,
    avatar: am.http.MultipartFile, // { filename, content_type, data }
};

fn uploadAvatar(c: *am.Context(App)) !void {
    const form = try c.req.multipart(Upload);
    if (form.avatar.content_type[0..6] != "image/"[0..6]) {
        return c.json(.{ .error_kind = "bad_image" }, 400);
    }
    // form.avatar.data はリクエスト arena に居る
    try saveAvatar(form.name, form.avatar.data);
    try c.json(.{ .ok = true }, 200);
}
```

Added `max_upload_bytes: usize = 50 * 1024 * 1024` to ServeOptions (default 50MB). If it exceeds 413 Payload Too Large.

### 3.3 Cookie/Session

```zig
// 読み取り
const sid = c.req.cookie("session") orelse return c.redirect("/login", 302);

// 書き込み
try c.setCookie("session", new_sid, .{
    .max_age_secs = 3600,
    .http_only = true,
    .secure = true,
    .same_site = .lax,
    .path = "/",
});

// Session ミドルウェア
var sessions = try am.mw.SessionStore.initMemory(alloc);
_ = try app.useAll(am.mw.session(State, .{
    .secret = "...",
    .cookie_name = "AKID",
    .store = &sessions.store,
}));

fn login(c: *am.Context(App)) !void {
    var sess = c.session();
    try sess.set("user_id", "alice");
    try c.json(.{ .ok = true }, 200);
}
```

### 3.4 Rate limit

```zig
_ = try app.use("/api/*", am.mw.rateLimit(State, .{
    .key_fn = byIp,
    .max_requests = 100,
    .window_secs = 60,
}));

fn byIp(c: *am.Context(State)) []const u8 {
    return c.req.ip() orelse "unknown";
}
```

### 3.5 Structured access log + request_id

```zig
_ = try app.useAll(am.mw.requestId(State));        // UUID を c.user_data に
_ = try app.useAll(am.mw.accessLog(State, .json)); // JSON 1 line per request

// 出力例:
// {"ts":"2026-05-22T12:00:00Z","req_id":"…","method":"GET","path":"/users/42","status":200,"latency_us":123,"ip":"1.2.3.4"}
```

## 5. Key technical decisions and risks

| Judgment | Adoption | Reason |
|---|---|---|
| Turso connection route | **Hrana HTTP via `am.http_client`** | Completely avoids D1's 2-pass barrier, same code in both environments |
| Handling of D1 | **Downgraded to deprecated**, Turso recommended | Hrana synchronization semantics is better compatible with Akamata's vtables ◎ |
| multipart upper limit | Default 50MB, change with ServeOptions | Real solution for DoS protection |
| Session store | Plug-in type of in-memory + `Db` backend | Turso/D1 as store when scaling |
| Embedded Replica | **Skip in v0.2** (`-Dwith-turso-replica` in P3) | Rust toolchain dependencies default off |
| MQTT/WS for Workers | **Unsupported documentation clearly stated** | Realistically, replacement with Cloudflare Queues / DO is required, another milestone |

### Risk

1. **Hrana error model mapping** — JSON `{type:"error",...}` must be mapped to `DbError` without exception. Test vector required
2. **Row data lifetime** — Need to keep Hrana response JSON in arena. Safe until Stmt.deinit
3. **Robustness of multipart implementation** — boundary parsing, nesting, CRLF, termination markers — emphasis on test coverage
4. **Session middleware signed cookie** — Sign with HMAC-SHA256, option to include jti in replay protection
5. **OpenAPI automatic generation has been postponed for now** — Comptime reflection has a high cost of creation, v0.3 candidate

## 6. Final policy (agreed on 2026-05-22)

1. **Scope**: Phase 1+2+3 + examples/mobus transparentization (about 18-20 days)
2. **Turso Test**: Hrana JSON specification compliant unit tests with HTTP mocks. Actual Turso operation confirmation procedure is described in docs/en/db-backends.md
3. **Handling of D1**: **Keep both in first-class**. Complete the 2-pass coroutine conversion of D1 in v0.2 (make D1 real). Align with Turso
4. **multipart limit**: Default 50MB (can be changed in ServeOptions)
5. **examples/mobus**: Make both environments work with the same `main.zig` (`worker.zig` is abolished, the same entry in build.zig)
